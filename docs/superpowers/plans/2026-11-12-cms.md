# nosMedia CMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Carson can log in from a gear in the footer of any page and edit every piece of text, replace every video and photo at full quality, and grow, shrink and reorder the service, slider and Work lists.

**Architecture:** This ports CaptureWithKi's inline CMS (`~/capturewithki/cms/`) into the 7-page static site. Plain ES modules in `cms/` load content from Firestore (`content/site`, `content/settings`, and the `services`/`slides`/`films` collections) and overwrite the HTML fallbacks. While editing, text is `contenteditable` and media slots open a picker that sniffs the codec (H.264 only), then uploads untouched to Cloud Storage with a resumable upload. `js/site.js` exposes a small `window.NOSSite` hook API so content the CMS re-renders gets the same autoplay, slider and reveal wiring.

**Tech Stack:** Static HTML/CSS/JS on GitHub Pages (no build step). Firebase Web SDK `10.13.0` from gstatic (Auth, Firestore, Storage). Node 24 `node --test` for the pure modules. Firebase CLI for deploying rules.

**Spec:** `docs/superpowers/specs/2026-11-12-cms-design.md`

## Global Constraints

- No build step and no bundler. No `package.json` at the repo root. Tests run with `node --test tests/` (Node 24 detects ESM syntax in `.js` files).
- Every gstatic import is pinned to exactly `https://www.gstatic.com/firebasejs/10.13.0/…`.
- `cms/no-indexeddb.js` is the first `<script>` in `<head>` on every page, before any module.
- Sign-in uses `browserSessionPersistence` (tab only), the same as CaptureWithKi's `auth.js`.
- Never run a bare `firebase deploy`. Always `firebase deploy --only firestore:rules,storage --project <id>`.
- Uploads go up byte-for-byte. **No transcoding, no shrinking.** The only thing generated is a JPEG poster still.
- Video accepted only if its sample entries include `avc1`/`avc3` and none are `hvc1`/`hev1`/ProRes (`apcn apch apcs apco ap4h ap4x`).
- Max upload 2GB (`2 * 1024 ** 3` bytes). Warn (confirm dialog, not a block) above 1GB (`1024 ** 3`).
- The old Storage file is deleted only after the new URL is saved, and only if it's a file in this project's bucket (never `media/…` bundled files).
- Keep `<meta name="robots" content="noindex">` on every page.
- Carson's phone number never appears anywhere. Contact routes are email, the form and Instagram.
- Content keys: `shared.*` for things repeated across pages, `<page>.<section>.<name>` otherwise (page = `home|work|services|about|book|contact|review`).
- Pure modules (`cms/video-check.js`, `cms/derive.js`, `cms/collection-order.js`, `cms/storage-paths.js`) import nothing from gstatic, so Node can test them.

## Review Focus

1. **Picking a video from the iPhone Photos library.** iOS Safari may re-encode a picked video ("Compressing…") before the page ever sees it. That's a silent quality loss. Expected: the picker sets `accept="video/mp4,video/quicktime"`, and the upload screen's tip tells Carson to use **Choose File → Browse** (the Files app) for full quality. This gets checked on a real iPhone in Task 10.
2. **A non-faststart export (moov box at the END of a 1.5GB file).** Expected: the codec check still finds the codec by walking the top-level boxes and reading only `moov`, never the whole file. The test is in Task 2.
3. **Upload cancelled, or the network drops partway (phone locks).** Expected: the live video is unchanged, no Firestore write happens, and a plain message appears. The test is in Task 7.
4. **Firestore slow or unreachable.** Expected: the HTML fallback text appears after at most 3s, and nothing stays hidden. The test is in Task 6.
5. **Editing a `.reveal-text` line, or pasting styled text from Notes.** Expected: the stored value is plain words, with no `<span class="w">` word wrappers and no `style=`. The test is in Task 6.
